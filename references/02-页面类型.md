# 02 · 页面类型（act）

`slides[].act` 决定学生端那一页渲染成什么。大屏永远是「配图 + 标题 + 当前页实时统计」，
**交互只发生在学生端**——这是这套设计的关键：老师负责讲，学生负责做。

---

## 通用：纯图文页（`act: null`）

最常见的一种。学生端显示正文 + `students` 提示语，大屏显示配图 + 标题 + 本页统计。

配图缺了会显示占位框（虚线 + 文件名），不影响上课，**别让占位框吓到老师**——
课前用 `verify.py` 查一遍图片是否齐。

---

## quiz · 单选题

```js
S('🧩 分解思维', '刚才我们把大问题拆成了小问题 —— 这种方法叫什么？', 'quiz', ['q1'], '先想一想，再选答案。', '活动一 · 分解', 2, …)
```

- 学生端点选项 → `submitQuiz` → 服务端判分 → 立即回显对错 + `points` 分。
- **答案只在 `answers.js`**，客户端只有题面。学生按 F12 也看不到答案。
- 分值按 `points`（默认 2）。一节课 1–3 题，别多。
- 大屏显示「已答 n / 总人数」，不显示对错——避免还没答的学生抄。

**为什么判分要走服务端**：这是这套系统唯一"必须联网"的时刻。断网时走本地降级，
判分改用本地 `answers`（如果 course.js 里带了），课堂不至于卡住。

---

## mindmap · 两层动手分解

- 第一层：4 张主分支卡拖进 4 个空框（拖哪个框都行，等价）
- 第二层：全部主分支放好后，小任务卡才出现，拖到对应分支下面
- 进度：`主分支 n/4 · 小任务 m/8`，全放完 +2 分/组
- 学生可以点卡片右上角 ✕ 撤回

**为什么分两层**：先让学生把"大问题"切成 4 块，再切细。一次给 12 张卡会直接懵。
第二层锁住的交互（`locked`）就是这个教学意图，别为了"自由"拆掉。

---

## claim · 认领岗位

- 一岗一人：被别人占了就置灰；**认领后不能改**
- 教师组（`demo:true`）例外：可多人同岗、可随时换，用来试讲
- 认领成功后，本岗位的 `subProblems` 直接出现在同一页下面（这就是 `pick` 页在学生端被折叠掉的原因）

**「认领后不能改」是有意的。** 课上改岗位会让整组重来；要允许改就得重算所有已填内容。
如果确实需要，告诉学生"刷新页面重选"比做改选功能更省事。

---

## pick · 从混池里挑自己的子问题

- 把所有岗位的 `subProblems` 打乱混在一起（默认 8 条）
- 学生挑出属于自己岗位的（默认 2 条），全对才算过，+2 分/人
- 挑错不扣分，可以重挑

**这一页的教学价值最高**：学生必须真的理解"我这块负责什么"才能挑对。
上完课问"你为什么觉得这条不是你的"，比问答案本身更有用。

---

## useAgent · 向岗位 AI 提问

学生端流程：

1. 填四张卡（角色 / 目标 / 知识 / 规矩）——每张卡有默认值，可直接改
2. 可选：把「坏规矩」那张换上去，对比问出来的答案
3. 提问 → `POST /api/agent` → 服务端拼 system prompt 调模型 → 返回
4. 对话记录按人隔离，同组同学互相看不到

AI 的完整链路见 `03-AI岗位链路.md`。这里只记课堂用法：

- **一定要让学生先填卡再提问**。不填卡直接问，等于把 ChatGPT 当搜索用，这节课就废了。
- **「误信 AI」那一页要紧跟在提问之后**。学生刚被 AI 说服，紧接着看到反例，冲击最大。
- AI 说的话要"记下来等会儿核实"——所以下一页必须是 `platform`，形成闭环。

---

## platform · 用课前录好的真实数据核实

点开按钮 → iframe 打开 `/platform.html?role=…&city=…&kind=…`，数据来自本机
`public/platform-data.js`。**上课不连外网**：不弹登录、不撞验证码、不受机房网速影响。

数据结构（每个城市的四类数据 + 每条都带来源和查询日期）：

```js
window.PLATFORM_DATA = {
  meta: { title:'…', from:'日照', date:'2026年10月1日', nights:'1 天 1 夜', asof:'2026年9月15日' },
  traffic: { '济南': { note:'…', direct:[{ no:'G5598', fromSt:'日照站', dep:'08:05',
             toSt:'济南站', arr:'11:24', dur:'3小时19分', price:'181', type:'高铁' }] } },
  sights:  { '济南': [ … ] },
  hotels:  { '济南': [ … ] },
  food:    { '济南': [ … ] },
  snap:    { traffic:{ '济南':[['车次','G5598'],['用时','3小时19分']] } }   // 顶部"关键信息"区
};
```

**`src`（来源）和 `asof`（查询日期）是课堂内容，不是技术字段。**
这一页要教的就是"信息要看是谁说的、什么时候说的"，随手删掉就白做了。

课前准备：按组的目的地各查 1–2 条真实车次/门票/房价/人均，填进 `platform-data.js`。
**查 6 个组 × 4 类 = 24 条，40 分钟能弄完**，比上课现场打开携程稳得多。

## itinerary · 小组行程卡

- 4 行（来自 `cardRows`），每行含「文字 + 截图」两列
- **每人只能改自己岗位那一行**（`canEditRow`），别人那行是只读
- 某行岗位没人认领时，本组谁都能补（防止 4 人组里有人请假就填不了）
- 截图：点格子 → `Ctrl+V` 直接粘（走 `/api/upload-card`），或由课堂截图工具自动贴

**为什么按行锁**：不锁的话，一个学生手快把 4 行都填了，其他 3 个人整节课没事干。
这是分组教学能不能成立的关键机制，别为了"方便"放开。

---

## report · 成果汇报 + 互评

- 学生端显示所有组的行程卡（含截图缩略图）
- 给**除自己组以外**的每组打 1–5 星，星数 × 2 计分，**每组只打一次，不能改**
- 自己组那张卡会标「我们组」，星星是禁用的

**不给自评**是硬规则。放开的话每组都给自己 5 星，互评就失去意义。

---

## reflect · 迁移一句话

学生写一句"这个方法你想用在哪件事上"。服务端只存文本，大屏汇总显示。
**别加评分**——这一页的目的是让老师看到谁真的懂了，打分会让学生写套话。

---

## 页序设计（一节课的骨架）

推荐的 16 页节奏（黄河课实测 37 分钟）：

| 环节 | 页数 | 内容 |
|---|---|---|
| 创设情境 | 3 | 封面 → 收到委托 → 抛问题 |
| 活动一 · 分解 | 4 | 概念题 → 动手导图 → 认岗位 → 挑子问题 |
| 活动二 · 分工规划 | 4 | 问 AI → 反例视频 → 平台核实 → 填行程卡 |
| 活动四 · 汇报 | 1 | 各组展示 + 互评 |
| 活动五 · 迁移 | 4 | 感谢信/回顾 → 方法三步 → 还能用在哪 → 下课 |

## 延迟播放（`manualVideo`）

```js
Object.assign(V(S(…), ['/videos/demo.mp4'], '', 'slide'), { manualVideo: true })
```

翻到这页先显示图文，老师**再按一次「下一页」**才整页播视频，播完回到图文。

用途：老师要先讲两句再放演示。**这不是 bug，是刻意设计的第二段触发器**，
清理代码时不要当成"多余的判断"删掉。
