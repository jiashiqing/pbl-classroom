# 03 · 岗位 AI 链路（这套东西最值钱的部分）

目标不是"接个大模型"，是**让 4 个 AI 助手各说各的，不越界**。

小模型（课堂要快，只能用 flash 级）天然不听话：你让它只讲交通，它热情地给你排一整天行程。
所以这里做了**四层防线**，任何一层都不能省。

```
学生填的四张卡
   ↓
① buildSystemPrompt  —— 把岗位范围写成硬约束（不是"建议"，是"绝对不要"）
   ↓
② 调用参数            —— 低配快模型 + 压掉推理 + 4xx 自动去参重试
   ↓
③ scopeFilter        —— 句子级兜底：模型还是串岗了，就按关键词逐句删
   ↓
④ offlineAnswer      —— 没配 key / 调用失败，返回结构化示例，课堂不中断
```

---

## ① buildSystemPrompt：把范围写成硬约束

输入：学生填的四张卡 + 本组目的地 + 出发地 + 时长。

### 岗位判定

```js
const r = ROLES.filter(x => x.scope && x.scope.name && role.indexOf(x.scope.name) >= 0)[0];
```

`role` 是学生填的「我是交通规划师助手」，`scope.name` 是「交通」。命中即锁定。
**所以 `scope.name` 必须是岗位名里的连续子串**——「交通规划师」里要有「交通」。
自己造岗位名时先对一下，不然 AI 会退化成"通用助手"，什么都答。

### 硬规则（逐条都在解决真实事故）

| 规则 | 解决什么 |
|---|---|
| 每条建议都要说清是在「{dest}」怎么安排，不许用"目的地""那里"代替 | 模型爱说"你可以在目的地附近…"，学生抄进行程卡就是废话 |
| 提到的地点必须都在「{city}」，绝不能出现出发地或其它城市 | 学生会拿到"从济南出发去济南"这种答案 |
| 绝对不要改写目的地，不要说"可以先确定具体目的地" | 模型觉得目的地不合理就会自作主张换一个 |
| 只在「{duration}」范围里说，不许出现"第二天""次日返程" | 1 天 1 夜的行程被排成 3 天 |
| 讲交通时必须写清「从{origin}怎么到{dest}」 | 只说"可以坐高铁"，不说从哪到哪 |
| 不确定的信息（票价/班次/开放时间/价格）必须说"这需要查证" | **这条是教学目的**：让学生知道 AI 会编 |

最后一条最重要。这节课教的是"AI 说的话要核实"，如果 AI 自己就很诚实，课就没得上了；
但也不能让它故意骗人——**要让它「自信地说，但该查的地方明确说该查」**。

### 输出格式约束

```
输出要求：中文、分条、每条一句话，最多 4 条，每一条都必须是关于【交通】的，出现景点、住宿、美食就算错。
```

**限条数**是关键。不限的话模型会写 800 字小作文，学生在课堂上根本读不完。
4 条 = 一眼扫完 + 够填行程卡。

## ② 调用参数：为"课堂 3 秒内出结果"调

| 参数 | 值 | 为什么 |
|---|---|---|
| `model` | flash 级（如 `deepseek-flash`） | 课堂等待超过 5 秒学生就开始走神 |
| `reasoning_effort` | `none` | 推理模型会把 2 秒变成 15 秒，这类任务不需要推理 |
| `temperature` | 0.3 左右 | 太低答案千篇一律，太高会跑题 |
| `max_tokens` | 300–500 | 配合"最多 4 条"，给多了必然注水 |
| `timeoutMs` | 45s | 兜底，实际不应超过 5 秒 |

实测：`deepseek-flash` + `reasoning_effort=none` ≈ **1.5 秒**返回。

**4xx 自动去参重试**：有些兼容 OpenAI 协议的服务不认 `reasoning_effort` 这类字段，
会直接 400。所以第一次带全参，失败后去掉可选参数再试一次——**不能因为参数不被识别就让课堂 500**。

密钥只放服务端（`config.json` 或环境变量），**永远不要出现在 public 里**。

## ③ scopeFilter：句子级兜底

小模型即使读了硬约束，还是会有 1–2 句串岗。这里做最后一道：

```js
function scopeFilter(answer, scopeName) {
  const own = DOMAIN_KW[scopeName];                                  // 本岗位词
  const others = 其它岗位的词全摊平;
  const lines = answer.split('\n').map(去编号).filter(Boolean);
  const kept = lines.filter(line => !(命中别的岗位词 && 没命中本岗位词));
  return (kept.length ? kept : lines).map((s,i) => `${i+1}. ${s}`).join('\n');   // 删空就退回原文
}
```

三个细节都是有教训的：

1. **按行删，不是按段删。** 模型的分条输出天然一行一条，按行删粒度刚好。
2. **「命中别的 + 没命中本岗位」才删。** 只命中别的就删太激进——"从日照站坐高铁到济南站，出站打车 15 分钟到景区"这句同时含交通和景点，是合格的交通答案。
3. **删空了退回原文。** 宁可让学生看到一句串岗的话，也不能给一片空白——空白会被当成"AI 坏了"。

`kw` 的写法：**写"别的岗位不会说的词"**。「吃」这种词会误伤（"吃完早饭就出发"），
「餐」「人均」「特色菜」更准。

## ④ offlineAnswer：课堂绝不能因为 AI 挂了而停

触发条件：没配 key、key 失效、超时、网络断。

做法：**先按「问题」判意图，问题看不出意图时才用「岗位」兜底**。

```js
if (/预算|多少钱|花多少|费用|省钱/.test(q)) kind = 'budget';
else if (/住|民宿|酒店|吃|餐|美食/.test(q)) kind = 'stay';
...
if (!kind) { 按岗位 scope.name 映射 }
```

> **早期版本踩过的坑**：一开始把岗位名也放进第一轮匹配，结果「景点推荐官」问"预算多少"会命中
> "景点"分支，答非所问。**问题优先、岗位兜底**这个顺序不能反。

预置 8 类答案：`traffic / spot / stay / budget / safe / coord / guide / general`。
每类都带上真实的出发地、目的地、时长，学生看不出是离线货。

返回顶部会加一行：`（演示模式：未配置真实AI，以下为内置示例回答）`。
**这行不能删**——老师要知道现在是演示模式，别以为接好了。

## 检查清单

上线前跑一遍：

- [ ] 用交通岗问「帮我安排一整天的行程」→ 应该只给交通，并说"其它是别的岗位的事"
- [ ] 用景点岗问「住哪」→ 应该说"那是住宿管家负责的"，而不是硬答
- [ ] 用任意岗问「门票多少钱」→ 必须出现"需要查证"
- [ ] 把 `config.json` 改名 → 提问仍然有答案，且顶部有"演示模式"提示
- [ ] 把 key 改成错的 → 不报 500，走离线降级
- [ ] 学生提问的记录，同组其他人看不到（按 `member` 隔离）

## 换模型时要注意

只改 `config.json` 的三行（`openaiBaseUrl` / `openaiApiKey` / `openaiModel`）。
**不要改 prompt 结构**——四层防线是跟"小模型不听话"这个前提配套的，
换成大模型后 `scopeFilter` 可能一次都不触发，但**留着**：课堂上网络抖动时可能就是它救了场。
