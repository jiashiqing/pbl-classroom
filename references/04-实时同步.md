# 04 · 实时同步与状态

## 一句话架构

**服务端持有唯一权威 state，所有客户端拿全量、自己过滤。**
没有增量 diff，没有客户端写入权限。500 人的场面也不需要，机上 6 组正好。

```
学生端 ──POST /api/state {action,payload}──▶ 服务端 applyAction 改 state
                                              │
学生端/大屏 ◀──SSE /api/events 全量 state──────┘   （60ms 合并，防抖）
```

## state 结构

```js
{
  title, origin, duration,     // 来自 course.js 的 meta
  session,                     // 每次重启换一个 8 位 id，用于"课堂数据已重置"
  slide,                       // 当前页下标，老师翻页写的
  teams: [ team… ],
  ratings: { 被评组id: { '打分人@组id': 星数 } },
  audit: [ … ],                // 事件流水，只在服务端留，不下发（否则每次广播都变胖）
  connected                    // 当前连接数
}
```

`team`：

```js
{
  id: 'T1', name, color, demo, dest,
  members: ['小明'],           // 组员名
  score: 0, badges: [],
  answeredBy: { 小明: { q1: { chosen, correct } } },   // 选择题按人记
  roleClaims:  { '交通规划师': '小明' },                // 岗 → 人，用来置灰按钮
  memberRoles: { '小明': '交通规划师' },                // 人 → 岗，**身份以这个为准**
  mindMap: { nodes: [], submitted: false, scored: false },
  picks:   { 小明: { role, picked:[…], correct } },
  agent:   [ { from, text, at } ],     // 按 member 隔离，每人只看自己的
  selfAwards: { 小明: 2 },             // 自助加分次数
  card:    { '交通工具': { t, img } }   // 共享行程卡
}
```

**为什么 `memberRoles` 和 `roleClaims` 两份都要**：
`memberRoles` 回答"我是谁"，`roleClaims` 回答"这个岗位被谁占了"。
教师组允许多人同岗，那时只写 `memberRoles`、不写 `roleClaims`——两份合并成一份就表达不了这个。

**`audit` 不下发**：它是给老师事后查的流水，前端根本不显示。跟着广播发只会让每次推送变胖。

## 13 个 action

| action | payload | 谁调 | 作用 |
|---|---|---|---|
| `joinTeam` | teamId, member | 登录页 | 进组 |
| `claimRole` | teamId, member, role | claim 页 | 认领岗位 |
| `submitQuiz` | teamId, member, qid, chosen | quiz 页 | 判分，返回 `{correct, points, awarded}` |
| `setMindMap` | teamId, nodes, submitted | mindmap | 导图节点整组替换 |
| `submitPick` | teamId, member, role, picked | pick | 子问题作答，返回是否全对 |
| `setCard` | teamId, member, key, t | itinerary | 写行程卡一行文字 |
| `setCardImg` | teamId, member, key, img | itinerary | 写行程卡一行图片（只认 `/uploads/` 内的） |
| `rateTeam` | teamId, rater, stars | report | 互评打星 |
| `selfAward` | teamId, member | 任意 | 自助 +5 |
| `logAgent` | teamId, member, q, a | useAgent | 记一条 AI 对话 |
| `setSlide` | slide | 大屏 | 翻页 |
| `bindDevice` | teamId, member, deviceId | 截图工具 | 设备号 → 人 |
| `resetAll` | — | 教师端 | 清课堂数据（换 session） |

**客户端发什么，服务端就必须有什么。** `verify.py` 会对这两张表做差集，
多出来的 case 就是死代码，少一个就是运行时报 500。

## 身份识别（谁的电脑是谁）

三层，逐级兜底：

1. **设备号**：本机 `127.0.0.1:45678` 报 deviceId → 学生端 `bindDevice` → 服务端记 `deviceIdentity`
2. **IP**：同一出口 IP 兜底（一人一机时成立）
3. **localStorage**：`cls_me = {teamId, name, session}`，页面刷新不丢

**云教室/机房经常一个出口 IP 出去几十台机器**，所以设备号优先、IP 只兜底。
如果学校是 NAT 出口，一定要装截图工具（或让学生手动在登录页选组），否则会串号。

`session` 对不上说明课堂数据重置过，客户端会弹"请重新登录"——这是**正常行为**，不是 bug。

## 广播

```js
function broadcast() {
  if (bcastTimer) return;
  bcastTimer = setTimeout(() => { bcastTimer = null; 推给所有 SSE 客户端 }, 60);
}
```

60ms 合并：导图拖拽一秒能触发几十次，不合并会把浏览器打满。

**SSE 断线重连**：浏览器 `EventSource` 自带重连，服务端每次连接先发一条 `event: hello`。
反代部署时必须 `proxy_buffering off` + 长超时，否则事件会被攒着一起发。

## 本地降级（`netMode === 'local'`）

连不上服务器时，`Net` 自动切到本地模式：

- 状态写 `localStorage`
- 同机多标签用 `BroadcastChannel` 同步
- 顶部出现提示条：**「当前为本地演示（未连接课堂服务器）」**

**这个模式的价值**：老师在家备课、或者机房断网时，页面不会白屏，能继续演示。
但**它不能让多台学生机同步**——那必须靠服务器。提示条写清楚，别让人误以为在上课。

## 计分表

| 项 | 分值 | 上限 |
|---|---|---|
| 选择题答对 | `points`（默认 2）/题 | 按题数 |
| 导图全放完 | 2 / 组 | 1 次 |
| 子问题全挑对 | 2 / 人 | 1 次 |
| 自助加分 | 5 / 次 | **无上限** |
| 互评 | 星数 × 2 | 每组只能打一次 |

**自助加分没有上限**是一个已知的口子：手快的学生能一直点。
设计意图是"答完题给自己鼓励"，实际会变成刷分。
如果要收，在 `selfAwards` 上加个 `times < 1` 判断；**但这是玩法改动，先问过老师再动**。

徽章（目前三个）：

- `答题王` —— 答对过题
- `拆解大师` —— 导图全放完
- `岗位小专家` —— 子问题全挑对

## resetAll 注意

`resetAll` 会换 `session`，所有客户端随即要求重新登录。
**上课前别乱点**——它没有二次确认。要保留历史就用导出，别指望这个。
